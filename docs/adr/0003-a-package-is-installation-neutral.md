# A Package is Installation-neutral

A VC Lab Package's files keep the local stack's addresses, `http://vdr.localhost` and `http://cdn.localhost`: `template.html` is the uploaded template byte for byte, and the credential file is the uploaded one apart from the Background's address. Template-sync is the one place local addresses become an Installation's: it rewrites the credential file to its `VDR_BASE_URL` when it stores the file in Certify. So one Package places on any Installation, and Load Package gives back exactly the files exported.

A template loads nothing by address. The Background comes only through `$backgroundImage`, which the Wallet fills from the credential file's `display[0].background_image.uri`; a template's own addresses aren't rewritten anywhere, and anything it loads by address answers 422 in VC Lab. With a Background, the Package sets that `uri` to the fixed path `http://vdr.localhost/templates/<config id>/<version>/background.png`, and the Package's `background.png` is placed there; an address on that path counts as correct configuration, not as something to rewrite. The VDR address typed at export stays in `manifest.json` as `vdrAddress`, a label for the VDR follow-up spec's publish step: no file content depends on it.

Considered: rewriting the local addresses to the typed VDR address at export, and replacing that address back with `http://vdr.localhost` on Load. Rejected: the plain-text replacement on Load corrupted unrelated addresses that happened to contain the VDR address, and the export rewrite needed three fixes before a second pass changed nothing (an address already written as the VDR's, a VDR address that starts with `http://vdr.localhost`, and one that starts a local address, such as `http://vdr`).
